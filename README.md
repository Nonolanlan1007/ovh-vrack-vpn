# OVH vRack VPN

OpenTofu/Terraform config that deploys a small WireGuard VPN endpoint on OVHcloud Public Cloud and attaches it to a vRack private network. Connect from your laptop and reach every private instance in the vRack subnet without exposing them to the internet.

## What it does

- Creates one Debian 13 instance with a public IP and a second NIC on your vRack private subnet.
- Generates the WireGuard server key, client key and preshared key, and installs the server through cloud-init.
- Outputs a ready-to-import WireGuard client config that routes the tunnel network (`172.16.0.0/24`) and your vRack subnet through the VPN.

## Limitations

- **Destroying the stack means recreating every credential.** All WireGuard keys are generated by the stack and live in its state. After a `destroy` and `apply`, the server and client keys are new, so you must re-import the new client config on every device.
- The public IP is assigned by OVH, so it can change when the instance is recreated. The client config embeds it.
- Single instance, single client, no high availability.

## Prerequisites

- [OpenTofu](https://opentofu.org) (or Terraform)
- An OVHcloud Public Cloud project with a vRack private network and subnet
- A service account with the IAM policy below

## Create the service account

The OVH provider authenticates with OAuth2 client credentials (a service account), not the legacy application key and consumer key.

### 1. Create the service account

1. Log in to the [OVHcloud Control Panel](https://manager.eu.ovhcloud.com) and open your account menu (top right) → **Identity, Security & Operations (IAM)**.
2. Go to the **Identities** tab and select **Service accounts**.
3. Click **Create a service account**.
4. Enter a name (e.g. `tofu-vrack-vpn`) and a description, then confirm.
5. Copy the **Client ID** and **Client Secret**. **The secret is shown only once**, so save it now.

### 2. Create the IAM policy

1. In **Identity, Security & Operations (IAM)**, open the **Policies** tab and click **Create a policy**.
2. Enter a name (e.g. `tofu-vrack-vpn`).
3. **Identities:** add the service account you just created.
4. **Resources:** add your Public Cloud project, and the `ovh-default` resource group.
5. **Actions:** choose to allow specific actions and add each action from the list below.
6. **Conditions (optional):** add a condition restricting the policy to your own public IP, so the credentials only work from your machine. If your IP changes, the provider fails with a 403 until you update the policy.
7. Save the policy.

Allowed actions:

```
publicCloudProject:apiovh:instance/create
publicCloudProject:apiovh:instance/get
publicCloudProject:apiovh:instance/edit
publicCloudProject:apiovh:instance/delete
publicCloudProject:apiovh:instance/usePublicIP
publicCloudProject:apiovh:region/instance/create
publicCloudProject:apiovh:network/subnet/get
publicCloudProject:apiovh:reference/instance/flavor/get
publicCloudProject:apiovh:reference/instance/image/get
```

The policy is scoped to a single project, so the service account can't touch anything else in your account.

## Configure

1. Copy the environment file and fill in the service account credentials:

   ```sh
   cp .env.example .env
   ```

   ```sh
   OVH_ENDPOINT=ovh-eu
   OVH_CLIENT_ID=<clientId>
   OVH_CLIENT_SECRET=<clientSecret>
   ```

2. Set your variables in `variables.tfvars`:

   | Variable | Required | Default | Description |
   | --- | --- | --- | --- |
   | `pc_project_id` | yes | | Public Cloud project ID |
   | `private_network_id` | yes | | ID of the vRack private network |
   | `private_network_subnet_id` | yes | | ID of the subnet to attach to |
   | `pc_region` | no | `GRA9` | Region of the VPN endpoint |
   | `instance_name` | no | `vpn-endpoint` | Instance name |
   | `instance_flavor` | no | `d2-2` | Instance flavor name |
   | `instance_image_id` | no | Debian 13 | Image ID override |
   | `private_network_instance_ip` | no | auto | Fixed IP inside the subnet |
   | `wireguard_port` | no | `51820` | WireGuard UDP port |

## Deploy

```sh
set -a; source .env; set +a
tofu init
tofu apply -var-file=variables.tfvars
```

Export the client config and import it into WireGuard:

```sh
tofu output -raw client_wg_config > vrack-vpn.conf
```

Treat `vrack-vpn.conf` like a password. It contains the client private key.

## Tear down

```sh
tofu destroy -var-file=variables.tfvars
```

The next `apply` generates new keys and a new client config. See [Limitations](#limitations).
